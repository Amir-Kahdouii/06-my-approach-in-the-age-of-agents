# مشخصات ارائه‌ی «ساختن دیگر گلوگاه نیست»

وضعیت: آماده برای پیاده‌سازی

## خلاصه

یک ارائه‌ی داستان‌محور، فارسی و ۱۶:۹ برای ضبط ویدیو و اشتراک‌گذاری صفحه ساخته می‌شود. ارائه از نگاه شخصی امیر به مهندسی نرم‌افزار در عصر هوش مصنوعی شروع می‌شود، با داستان واقعی فراموش‌شدن سفارش غذا در باشگاه ادامه پیدا می‌کند، شکست نسخه‌ی عمومی اولیه را نشان می‌دهد و در نهایت `pro-food` را به‌عنوان نمونه‌ای از ساخت سریع، ارزان و مسئله‌محور معرفی می‌کند.

پیام اصلی:

> در عصر هوش مصنوعی، ساختن دیگر گلوگاه نیست؛ پیدا کردن چیزی که ارزش ساختن دارد، گلوگاه است.

دعوت نهایی:

> ایده‌ات را سریع و ارزان بساز، اجازه بده نسخه‌ی اول شکست بخورد، از آدم‌های واقعی یاد بگیر و دوباره بساز.

## مخاطب و هدف

- مخاطب اصلی: مهندسان نرم‌افزار فارسی‌زبان
- لحن: دوستانه، شخصی، داستانی و شبیه ارائه‌ی یک بنیان‌گذار استارتاپ
- مدت هدف: ۷ تا ۸ دقیقه
- اقدام مورد انتظار: مخاطب به‌جای منتظر ماندن برای ایده‌ی کامل، مسئله‌ای واقعی از زندگی خودش را دنبال و یک نمونه‌ی کوچک از راه‌حلش را تجربه کند.
- هدف فرعی: معرفی شیوه‌ی کار و پروژه‌های امیر و فراهم‌کردن مسیر دنبال‌کردن آن‌ها

## خروجی‌ها

- پروژه‌ی React و Vite قابل توسعه
- خروجی production به‌صورت یک فایل مستقل `dist/index.html`
- تمام CSS، JavaScript، فونت، آیکون و تصاویر لازم داخل فایل نهایی قرار بگیرند.
- فایل نهایی بدون سرور و با بازکردن مستقیم در مرورگر اجرا شود.
- Workflow گیت‌هاب برای build و انتشار خودکار در GitHub Pages
- یادداشت گوینده برای هر اسلاید داخل خود ارائه

## جهت بصری

### زبان طراحی

- مینیمال، روشن و مناسب نمایش روی مانیتور و ویدیوی screen share
- جهت کلی رابط `rtl` و زبان سند `fa`
- هویت بصری مبتنی بر مرجع موجود در `DESIGN.md`: زمینه‌ی سفید، سبز جنگلی و سبز لیمویی
- رنگ‌ها:
  - Forest Ink: `#163300`
  - Lime Voltage: `#9fe870`
  - Linen Mist: `#e2f6d5`
  - Fog: `#e8ebe6`
  - Charcoal: `#454745`
  - Paper: `#ffffff`
- بدون گرادیان‌های تزئینی؛ کنتراست از جابه‌جایی بین سطح سفید، سبز روشن و سبز تیره ایجاد شود.
- بیشتر اسلایدها زمینه‌ی روشن داشته باشند؛ حداکثر دو اسلاید کلیدی از سطح سبز تیره استفاده کنند.
- کارت‌های glass فقط در اسلاید پایانی استفاده شوند تا به عنصر ویژه تبدیل شوند، نه زبان عمومی همه‌ی اسلایدها.

### تایپوگرافی فارسی

- فونت اصلی: Vazirmatn، به‌صورت محلی و inline در فایل خروجی
- تیترها: وزن ۸۰۰ یا ۹۰۰، فشرده و درشت
- متن‌ها و UI: وزن ۴۰۰ تا ۶۰۰
- اندازه‌ی تیتر اصلی در viewport استاندارد حدود ۷۲ تا ۱۰۴ پیکسل، با `clamp()` برای ابعاد کوچک‌تر
- هیچ متن ضروری کوچک‌تر از ۱۸ پیکسل در خروجی ۱۹۲۰×۱۰۸۰ نباشد.
- متن‌های روی اسلاید کوتاه و مناسب خواندن سریع باشند؛ جزئیات در speaker notes قرار بگیرند.

### موتیف اختصاصی

- یک cursor/نشانگر تایپ سبز به‌عنوان نشانه‌ی «ساختن» در نقاط محدود روایت تکرار شود.
- مسیر «زندگی تا یادگیری» تنها دیاگرام اصلی ارائه باشد.
- انیمیشن گم‌شدن رسید در اسلاید ۵ و شکستن قاب توسط واژه‌ی «همه» در اسلاید ۶، دو لحظه‌ی تصویری به‌یادماندنی ارائه باشند.
- از مجموعه کارت‌های یک‌شکل، اعداد تزئینی اسلاید و عناصر رایج قالب‌های SaaS پرهیز شود.

## رفتار ارائه

### ناوبری

- `ArrowRight`: رفتن به اسلاید بعدی
- `ArrowLeft`: برگشتن به اسلاید قبلی
- هیچ کلید دیگری اسلاید را جابه‌جا نکند.
- در ابتدا و انتها، کلید نامعتبر وضعیت را تغییر ندهد.
- navigation با کلیک روی صفحه انجام نشود تا هنگام تعامل با لینک‌ها اسلاید عوض نشود.
- شماره‌ی فعلی و تعداد کل اسلایدها به‌شکل کوچک نمایش داده شود.

## معماری پیشنهادی

- React + Vite
- یک آرایه‌ی مرکزی برای metadata اسلایدها: `id`، عنوان، مدت، speaker notes و component
- یک state سطح App برای index فعلی، جهت transition و وضعیت notes
- event listener کیبورد با cleanup صحیح
- CSS معمولی با custom properties؛ نیاز به framework استایل وجود ندارد.
- آیکون‌ها از پکیجی با SVG قابل tree-shake یا SVGهای inline استفاده شوند.
- QRها به‌صورت SVG یا data URL محلی تولید شوند.
- plugin تک‌فایل Vite برای inline کردن assetهای build
- وابستگی به CDN، فونت آنلاین یا API runtime مجاز نیست.

## GitHub Pages

- Workflow در `.github/workflows/deploy-pages.yml` قرار بگیرد.
- triggerها:
  - push روی شاخه‌ی `main`
  - اجرای دستی با `workflow_dispatch`
- permissionهای حداقلی مورد نیاز Pages تعریف شوند: `contents: read`، `pages: write` و `id-token: write`.
- job اول dependencyها را با lockfile نصب و build کند.
- artifact شامل محتوای `dist/` باشد.
- job دوم با action رسمی GitHub Pages artifact را deploy کند.
- Vite طوری تنظیم شود که فایل تک‌صفحه‌ای هم با `file://` و هم در subpath گیت‌هاب Pages asset شکسته نداشته باشد.
